## ১. সিক্রেট ফাঁস হলে (জরুরি প্রটোকল)
ধরুন `.env`-এর API key কমিট করে push করে ফেলেছেন।
1. 🔴 **প্রথমে সিক্রেট বাতিল/রোটেট করুন** (সার্ভিসের ড্যাশবোর্ডে)। ইতিহাস মুছেও লাভ নেই, কারণ ফাঁস হয়ে গেছে ধরে নিতে হবে (বট মিনিটে স্ক্যান করে)।
2. তারপর কোড থেকে সরান এবং `.gitignore`-এ যোগ করুন।
3. ইতিহাস পরিষ্কার (ঐচ্ছিক, লেসন ১৪-র `filter-repo`)।
4. প্রতিরোধ: `.env.example` কমিট করুন, `.env` নয়; GitHub secret scanning/push protection চালু রাখুন (⚠️ Settings → Code security; সব রিপোতে ডিফল্ট চালু নাও থাকতে পারে)।
- Next.js-এ `NEXT_PUBLIC_` প্রিফিক্সওয়ালা এনভ ভেরিয়েবল **ব্রাউজারে প্রকাশ হয়**: সিক্রেট রাখবেন না। 📖 nextjs.org/docs (এনভ ভেরিয়েবল অংশ ⚠️ আপনার ভার্সনের ডকে মেলান)।

## ৩. ফর্ক ওয়ার্কফ্লো (ওপেন-সোর্সে অবদান)
```bash
gh repo fork <owner>/<repo> --clone          # ফর্ক + ক্লোন (gh repo fork --help ✅ মেলান)
git remote -v                                 # origin = আপনার ফর্ক, upstream = মূল রিপো
git remote add upstream https://github.com/<owner>/<repo>.git   # না থাকলে
git fetch upstream
git switch main && git merge --ff-only upstream/main   # ফর্ক হালনাগাদ
git push origin main
git switch -c fix/typo-in-docs                # ব্রাঞ্চে কাজ → push origin → PR (মূল রিপোতে)
```
অবদানের আগে `CONTRIBUTING.md` ও `CODE_OF_CONDUCT.md` পড়ুন; আগে Issue খুলে আলোচনা করা ভদ্রতা।

## ৪. ব্রাঞ্চিং স্ট্র্যাটেজি: নিরপেক্ষ তুলনা
| স্ট্র্যাটেজি | কেমন | কখন মানায় | অসুবিধা |
|---|---|---|---|
| **GitHub Flow** | `main` + ছোট ফিচার ব্রাঞ্চ + PR | ওয়েব অ্যাপ, ক্রমাগত ডিপ্লয় | রিলিজ-ভার্সন ম্যানেজ আলাদা করতে হয় |
| **Trunk-based** | প্রায় সরাসরি `main`-এ ছোট ছোট পরিবর্তন + ফিচার ফ্ল্যাগ | পরিণত CI/CD, অভিজ্ঞ টিম | শৃঙ্খলা ও শক্ত টেস্ট দরকার |
| **Git Flow** | `main`, `develop`, `release/*`, `hotfix/*` | একাধিক সংস্করণ সমান্তরালে সমর্থন (যেমন ডেস্কটপ/লাইব্রেরি) | জটিল; ওয়েব অ্যাপে প্রায়ই অতিরিক্ত |
এই প্রজেক্টে (একা, ওয়েব অ্যাপ) **GitHub Flow** সবচেয়ে সহজ: এটা সুপারিশ, কিন্তু প্রসঙ্গ বদলালে উত্তরও বদলায়।
